# OARelatedWorkMetaEval

Code artifact for the paper *[OARelatedWork: A Large-Scale Dataset of Related Work Sections with Full-texts from Open Access Sources](https://arxiv.org/abs/2405.01930)*.

This repository lets you **meta-evaluate your own automatic judge / metric** for related-work-section generation against human judgments collected for the [BUT-FIT/OARelatedWorkMetaEval](https://huggingface.co/datasets/BUT-FIT/OARelatedWorkMetaEval) dataset. 

## What "meta-evaluation" means here

`OARelatedWorkMetaEval` contains human annotations of related-work sections generated by several models (and by humans) for papers from `OARelatedWork`. A judge (an LLM prompt, a heuristic metric, ROUGE, BERTScore, …) is only useful if its scores agree with these human judgments. This repo computes that agreement at two levels of granularity:

* **Coarse level** — one score per generated related-work section. The dataset provides a human-derived *factuality rate* per section (fraction of its atomic statements verified as strictly grounded). Meta-evaluation computes the **Kendall's tau correlation** between your judge's per-section scores and this human factuality rate, with a bootstrap confidence interval, and plots a violin plot comparing multiple judges at once.
* **Statement level** — one label per atomic factual statement extracted from a generated section. Each statement carries a human "meta" label (`True`, `True, but wrong citation`, `Unverifiable`, `False`). Meta-evaluation compares your judge's per-statement classification against these labels: a precision/recall/F1 report, confusion matrix and Cohen's kappa, computed both overall and on subsets (`All`, `Random Subset`, `Adversarial Subset`, `Human Disagreement Subset`), and in coarser binary groupings (`Ok`/`Faulty` and `True`/`False`).

Both workflows load the dataset directly from the Hub by default (`dataset_path: null` in the config), so no local data preparation is required.

## Meta-evaluating your own judge

The general flow is: **(1)** run your judge over the dataset and dump its scores/classifications to a `jsonl` file, **(2)** point a meta-eval config at that file, **(3)** run the corresponding workflow.

Both workflows are driven by a YAML config parsed with [`classconfig`](https://pypi.org/project/classconfig/). You can generate a starter config (with inline docs) for either workflow with:

```bash
python -m oarelatedworkmetaeval create_config coarse_meta_eval --doc config_doc.md > config.yaml
python -m oarelatedworkmetaeval create_config statement_meta_eval --doc config_doc.md > config.yaml
```

Fully worked example configs (including baselines such as ROUGE/BERTScore and several LLM judges) and their generated docs are in [`eval/coarse/`](eval/coarse/config.yaml) and [`eval/statement_level/`](eval/statement_level/config.yaml) — use them as templates.

### Coarse-level meta-evaluation

1. Run your judge on every `(target_paper_id, generated related-work model)` pair from the `duels`/`train` split of `BUT-FIT/OARelatedWorkMetaEval`, and write one score per line to a `jsonl` file:

   ```json
   {"target_paper_id": 123, "model": "gpt-5-4", "score": 0.83}
   ```

   Higher score is assumed to mean better/more factual.

2. Add a `FromFileCoarseScore` metric entry to your config, pointing `score_file` at that jsonl (a list — multiple files are averaged):

   ```yaml
   dataset_path:
   metrics:
     - cls: FromFileCoarseScore
       config:
         name: my-judge
         sample_results_file: my-judge_reference_free.jsonl
         reference_free: true          # or false for a reference-based judge
         score_file: [my_judge_scores.jsonl]
   results_file: coarse_results.jsonl
   violin_plot_file: coarse_violin_plot.pdf
   ```

   If your judge instead produces statement-level classifications (see below) and you want a coarse score derived from them (fraction of statements classified as `True`), use `FromFileStatementLevel2CoarseScore` with a `statement_cls_file` in the same format as the statement-level results below, plus `dataset_path` pointing to (or `null` to fetch) the `statements` config of the dataset.

3. Run it:

   ```bash
   python -m oarelatedworkmetaeval coarse_meta_eval config.yaml
   ```

   This writes, per metric, a line to `results_file` with the Kendall's tau statistic/p-value, a Shapiro normality test and a bootstrap confidence interval (plus the full bootstrap distribution), and (re-)renders `violin_plot_file` after each metric so you can inspect progress.

### Statement-level meta-evaluation

1. Run your judge on statements from the `statements`/`train` split of `BUT-FIT/OARelatedWorkMetaEval` and write one classification per line to a `jsonl` file, keyed by the dataset's `id` field:

   ```json
   {"id": 4821, "classification": "True"}
   ```

   `classification` should be one of `True`, `True, but wrong citation`, `Unverifiable`, `False`.

2. Add a `StatementClassificationResultFile` entry to your config:

   ```yaml
   dataset_path:
   results:
     - cls: StatementClassificationResultFile
       config:
         name: my-judge
         path: my_judge_statement_results.jsonl
         reference_free: true
   ```

3. Run it:

   ```bash
   python -m oarelatedworkmetaeval statement_meta_eval config.yaml
   ```

   This prints, per result file: the true-statement rate per generating model, then classification reports (precision/recall/F1, confusion matrix, Cohen's kappa) against the human meta-label for each statement subset and label grouping described above.

### Baseline metrics

Besides `FromFile*` wrappers around your own judge's output, the package ships a few reference metrics you can include in the same `metrics` list for comparison: `Rouge` (ROUGE-1/2/L, configurable precision/recall/F1), `BertScore`, and `BlockMatching` (paragraph/block-level matching on top of any string metric).

## Repository layout

* `eval/coarse/` — example coarse-level config, generated docs, and results/plot from the paper's own runs
* `eval/statement_level/` — example statement-level config and generated docs
* `oarelatedworkmetaeval/meta_eval.py` — the two meta-evaluation workflows (`MetaEvalCoarseWorkflow`, `MetaEvalStatementWorkflow`)
* `oarelatedworkmetaeval/metrics/` — metric implementations (`FromFile*`, `Rouge`, `BertScore`, `BlockMatching`)
